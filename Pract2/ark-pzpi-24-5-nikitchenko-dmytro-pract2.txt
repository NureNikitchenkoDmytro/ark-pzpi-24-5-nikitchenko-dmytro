2 ЗАВДАННЯ
Підготувати доповідь на тему «Методи рефакторингу коду програмного забезпечення». Обрати 3 методи рефакторингу з книги Р. Мартіна «Чистий код: створення і рефакторинг за допомогою AGILE» і навести код без рефакторингу та із застосуванням кожного методу на прикладі власного коду.
Обрані методи: Extract Method, Replace Nested Conditional with Guard Clauses, Introduce Explaining Variable. До доповіді оформити презентацію українською мовою (12 слайдів), відеозапис доповіді тривалістю 7-9 хвилин і звіт.
3 ОПИС ВИКОНАНОЇ РОБОТИ
3.1 Поняття рефакторингу
Рефакторинг - це зміна внутрішньої структури програми, яка робить код зрозумілішим і простішим для змін, не змінюючи його поведінки. Зміни робляться маленькими кроками, і після кожного кроку перевіряється, що програма дає той самий результат.
3.2 Програмний код для прикладів
Для прикладів використано мої Bash-скрипти, які працюють з таблицею оцінок з лабораторних grades.csv (додаток В.6): у кожному рядку прізвище, три оцінки і кількість пропусків. Скрипт stats.sh виводить середні бали, найкращого студента і кількість студентів із пропусками. Скрипт admit.sh визначає, чи допущений студент до іспиту: середній бал не менший за 60 і не більше двох пропусків.
3.3 Extract Method (виділення методу)
Суть методу: фрагмент коду, який можна згрупувати, виноситься в окрему функцію з назвою, що пояснює її призначення. Ознаки, що метод потрібен: довгий блок коду, коментарі перед частинами блоку, повтори.
У першій версії stats.sh (додаток В.1) весь код - один блок, частини якого підписані коментарями, а команда tail -n +2 (пропустити заголовок файлу) повторюється тричі. Після рефакторингу (додаток В.2) кожна частина стала функцією (print_averages, best_student, count_with_missed), повтор винесено у функцію students, а основна частина скрипта займає чотири рядки і читається як список дій.
3.4 Replace Nested Conditional with Guard Clauses (заміна вкладених умов сторожовими)
Суть методу: якщо вкладені умови перевіряють особливі випадки, ці перевірки виносяться на початок і одразу завершують роботу, а основна логіка лишається без зайвої вкладеності.
У першій версії admit.sh (додаток В.3) три перевірки (кількість аргументів, наявність файлу, наявність студента у файлі) вкладені одна в одну, основна логіка стоїть на четвертому рівні відступу, а повідомлення про помилки - далеко від своїх перевірок. Після рефакторингу (додаток В.4) кожна перевірка займає один рядок виду [ умова ] || die "повідомлення". Вкладеність зменшилась з чотирьох рівнів до одного, а скрипт - з 25 до 19 рядків.
3.5 Introduce Explaining Variable (введення пояснювальної змінної)
Суть методу: складний вираз або його частина записується у змінну з назвою, яка пояснює зміст.
Умова допуску в admit.sh (додаток В.4) займала один рядок довжиною 171 символ з вкладеними підстановками команд і числами 60 і 2 без пояснень. Після рефакторингу (додаток В.5) рядок файлу розбирається на змінні lab1, lab2, lab3, missed, середній бал записується в average, а числа замінено константами MIN_AVERAGE і MAX_MISSED. Умова тепер читається як речення: (( average >= MIN_AVERAGE && missed <= MAX_MISSED )).
3.6 Перевірка поведінки
Після кожного рефакторингу я перевіряв, що поведінка скриптів не змінилась. Вивід версій stats.sh до і після порівнювався командою diff, а версії admit.sh запускались для всіх випадків: без аргументів, з неіснуючим файлом, з відсутнім студентом, для допущеного, недопущеного і граничного студента (середній бал рівно 60 і рівно 2 пропуски). Результати всіх версій збіглися.
3.7 Презентація і відеозапис
За матеріалами роботи підготовлено презентацію з 12 слайдів (додаток Б) і записано відеозапис доповіді (додаток А). Програмний код прикладів розміщено в GitHub-репозиторії (додаток В).
4 ВИСНОВКИ
Було розглянуто поняття рефакторингу і три методи: Extract Method, Replace Nested Conditional with Guard Clauses, Introduce Explaining Variable.
Методи застосовано до власних Bash-скриптів: суцільний блок коду розбито на чотири функції з назвами, вкладеність перевірок зменшено з чотирьох рівнів до одного, а умову довжиною 171 символ замінено зрозумілими змінними і константами.
Отримано навички проведення рефакторингу маленькими кроками з перевіркою поведінки після кожного кроку: вивід усіх версій скриптів до і після рефакторингу збігся.
Отримано навички підготовки презентації та відеозапису доповіді.

В.1 Приклад програмного коду до рефакторинґу (Extract Method)
GitHub репозиторій: https://github.com/NureNikitchenkoDmytro/ark-pzpi-24-5-nikitchenko-dmytro/blob/main/Pract2/ark-pzpi-24-5-nikitchenko-dmytro-pract2/stats_before.sh
  1	#!/usr/bin/env bash
  2	# Статистика оцінок з лабораторних: ./stats.sh grades.csv
  3	set -u
  4	file=$1
  5	
  6	# середній бал кожного студента
  7	echo "Середні бали:"
  8	tail -n +2 "$file" | while IFS=, read -r name l1 l2 l3 _; do
  9	  echo "  $name: $(( (l1 + l2 + l3) / 3 ))"
 10	done
 11	
 12	# найкращий студент
 13	best=$(tail -n +2 "$file" | awk -F, '{ print int(($2 + $3 + $4) / 3), $1 }' | sort -rn | head -1 | cut -d' ' -f2)
 14	echo "Найкращий: $best"
 15	
 16	# скільки студентів мають пропуски
 17	count=$(tail -n +2 "$file" | awk -F, '$5 > 0' | wc -l)
 18	echo "З пропусками: $count"

В.2 Приклад програмного коду після рефакторинґу (Extract Method)
GitHub репозиторій: https://github.com/NureNikitchenkoDmytro/ark-pzpi-24-5-nikitchenko-dmytro/blob/main/Pract2/ark-pzpi-24-5-nikitchenko-dmytro-pract2/stats_after.sh
  1	#!/usr/bin/env bash
  2	# Статистика оцінок з лабораторних: ./stats.sh grades.csv
  3	set -u
  4	
  5	students() {          # рядки файлу без заголовка
  6	  tail -n +2 "$1"
  7	}
  8	
  9	print_averages() {
 10	  echo "Середні бали:"
 11	  students "$1" | while IFS=, read -r name l1 l2 l3 _; do
 12	    echo "  $name: $(( (l1 + l2 + l3) / 3 ))"
 13	  done
 14	}
 15	
 16	best_student() {
 17	  students "$1" \
 18	    | awk -F, '{ print int(($2 + $3 + $4) / 3), $1 }' \
 19	    | sort -rn | head -1 | cut -d' ' -f2
 20	}
 21	
 22	count_with_missed() {
 23	  students "$1" | awk -F, '$5 > 0' | wc -l
 24	}
 25	
 26	file=$1
 27	print_averages "$file"
 28	echo "Найкращий: $(best_student "$file")"
 29	echo "З пропусками: $(count_with_missed "$file")"

  2	# Чи допущений студент до іспиту: ./admit.sh grades.csv Іваненко

  6	  if [ -f "$1" ]; then

  8	    if [ -n "$line" ]; then
  9	      if [ $(( ($(echo "$line" | cut -d, -f2) + $(echo "$line" | cut -d, -f3) + $(echo "$line" | cut -d, -f4)) / 3 )) -ge 60 ] && [ "$(echo "$line" | cut -d, -f5)" -le 2 ]; then
 10	        echo "$2: допущений"

 16	      exit 1
 17	    fi
 18	  else
 19	    echo "Немає файлу $1" >&2

 21	  fi
 22	else

В.5 Приклад програмного коду після рефакторинґу (Introduce Explaining Variable)
GitHub репозиторій: https://github.com/NureNikitchenkoDmytro/ark-pzpi-24-5-nikitchenko-dmytro/blob/main/Pract2/ark-pzpi-24-5-nikitchenko-dmytro-pract2/admit_v3.sh
  1	#!/usr/bin/env bash
  2	# Чи допущений студент до іспиту: ./admit.sh grades.csv Іваненко
  3	set -u
  4	
  5	MIN_AVERAGE=60    # мінімальний середній бал
  6	MAX_MISSED=2      # максимум пропусків
  7	
  8	die() {
  9	  echo "$*" >&2
 10	  exit 1
 11	}
 12	
 13	[ $# -eq 2 ] || die "Запуск: $0 <файл> <прізвище>"
 14	[ -f "$1" ] || die "Немає файлу $1"
 15	line=$(grep "^$2," "$1")
 16	[ -n "$line" ] || die "Студента $2 немає у файлі"
 17	
 18	IFS=, read -r name lab1 lab2 lab3 missed <<< "$line"
 19	average=$(( (lab1 + lab2 + lab3) / 3 ))
 20	
 21	if (( average >= MIN_AVERAGE && missed <= MAX_MISSED )); then
 22	  echo "$name: допущений"
 23	else
 24	  echo "$name: не допущений"
 25	fi
